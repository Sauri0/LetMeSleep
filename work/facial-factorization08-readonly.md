## Concrete bounds for the motion export

Human camera pitch is clamped to −1.92..1.30 rad, while head pitch is one quarter: **−.48..+.325 rad**. Relative head yaw is ±75°. Torso yaw adds a separate gait term `sin(phase)*motion_blend*(1-air_blend)*.028`. Head-minus-torso center is `(0, .46-.10*crouch-settle-breath, -.08*crouch)`, where `settle=-.012*blend*(.5+.5*cos(2*phase))-.025*land_blend` and `breath=sin(pose_time*1.7)*.003*(1-blend)`. Tests should record the actor inputs and the resulting bone transforms rather than treating camera pitch as head pitch.

The exporter samples conservative poses, not spontaneous gameplay encounters. Finite endpoint/phase samples do not prove continuous clearance between them. The exact triangle auditor must retain that limit or supply a continuous bound. All variants are exported with coexistence rules; hidden alternatives must not be tested as though simultaneously equipped.

The exporter now calls `CharacterSkin.apply_facial_values` and reads every actual blend-shape value from each imported mesh. This includes internal brow/eyelid corrections and the later BrowUp×BrowDown interaction terms (seven internal corrective keys at this checkpoint). The ten public controller channels remain unchanged; internal correction geometry is a dependency of the complete applied mesh state.

## Exporter validation, before the final corrective import

Native smoke, `--case-limit=1`: one conservative human pose and one mosquito pose, 29 geometries, 45,956 vertices compared against the engine skeleton bake, 100,782 checks, zero failures, process exit 0, empty stderr. Maximum palette-versus-native difference was **0.00002618 m**; the gate limit is 0.00015 m. This validates the imported skin/bake bridge, not triangle intersections or the full pose set. Parse-only also exited 0.

Evidence: `work/facial-motion08-smoke.json`, `work/facial-motion08-smoke.stdout.log`, `work/facial-motion08-smoke.stderr.log`, `work/facial-motion08-parse.log`. The JSON records source/GLB hashes and checks that they stay unchanged during export. `summary.export_complete` is deliberately false for this limited run.

Full default sampling is 243 human cases (nine posture/phase witnesses × three head yaws × three camera pitches × three expressions) and 42 mosquito cases. The JSON has shared `topologies[name]`, `geometries[id].vertices`, `cases[].meshes[name].geometry`, actual per-mesh morph values, actual world bone transforms, imported skin weights and `compatible_pairs[role]`. Coordinates are rounded to 0.0000001 m. An exporter pass means a complete consistent data witness, not a collision-audit pass.

The runner `work/run-facial-motion08.ps1` partitions that set into nine human batches of 27 and two mosquito batches of 21, limiting each native process to 55 seconds. Its combined index requires all 285 case IDs exactly once, unchanged source/fixture/executable hashes, actual process exit 0, empty stderr, verified part hashes and a passing native-palette comparison. Each part has a `.json.index.json` sidecar; geometry IDs are local to that part.

An initial 27-case batch, stopped before the pending Blink repair, generated 13,013,936 bytes in 7.81 seconds (2.36 seconds before JSON serialization), with 341,478 compared vertices and no exporter assertion failures. **Its wrapper verdict is incomplete**, because Windows PowerShell 5 returned a null process exit code. That evidence was retained in `work/facial-motion08-final-parts/`; it is not the final dataset. The runner was corrected to retain the native process handle before waiting; an independent shell-child probe recovered both exit 0 and exit 7 correctly (`work/facial-motion08-exit-probe.log`). No missing exit status is treated as success.
