## Anclas y coordenadas

Se verificaron **50 posiciones** contra auditoría y FBX: Camp23 + Yate6 + Puerto21. `maps-03-05-offline-evidence.json` contiene rutas, tipos de nodo, coordenadas fuente/exportadas, error máximo y SHA256 de las fuentes. Transformación observada: Blender `(x,y,z)` → Unity `(x,z,y)`; FBX exportado `(x,y,z)` → Unity `(x,y,-z)`. No se aplica una conversión genérica a un dato ya convertido.

Yate tiene nodos Null `Environment/YATE_Anchor_Practical_*`. Puerto usa nodos Null `Environment/Anchor_LGT_*`, verificados en el FBX `_UNITY` de la receta, no sólo en nombres del reporte. El importer central preserva jerarquía, escala1 y no importa componentes Light; `suppressLightPaths` queda vacío.

**Campamento tiene nodos FBX Light `Environment/LGT_*`, sin anclas Null equivalentes.** El survey nativo posterior de Root confirmó que Unity preserva los 25 transforms con importLights=false. Comparación offline del readback `N:/LetMeSleep/Validation/Higgsfield/CampV2-20260913/preparation-02/camp-v2-preparation.json`: las 23 anclas configuradas coinciden dentro de 1 cm, con error máximo **0.00000107084 m**; los dos extras son LGT_Moon y LGT_Moon_Fill. No fue necesario cambiar el config ni crear anclas. El readback contiene nombres/posiciones; la confirmación del padre Environment proviene de Root. El resolver del catálogo todavía comprobará las rutas completas al ejecutar el fixture. Hashes y diferencias por ancla están en `camp-v2-native-anchor-comparison.json`; este resultado no constituye un Bind PASS ni una nueva ejecución Unity del worker.

La dirección del sol se obtiene del vector Blender local -Z de la matriz world auditada, se transforma a Unity y se expresa como Euler que orienta +Z de la luz Unity. No se copian los Euler Blender entre convenciones. La dirección resultante y Euler quedan en la evidencia.
