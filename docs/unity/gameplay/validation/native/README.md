# SurfaceVisualProbe — Director-only native recipe

This external diagnostic stays outside Assets. It does not modify Presentation, the imported model, scene files, gameplay rules or actor positions. Only the Director may run it in an assigned Unity slot. Offline compilation is API compatibility evidence; it is not a native contact, animation, visual, performance or WAN result.

## Build and identify

Run `./Compile-Probe.ps1` from this directory in PowerShell. The script creates a unique package under `N:/LetMeSleep/Validation/SurfaceVisual-20260912/probe-*` with the source, DLL, compilation receipt and eval_file snippets. Never copy the source or loader into Assets. Recompile after API changes against refreshed central ScriptAssemblies; their SHA256 values are recorded, and their timestamps can differ from source HEAD. Record actual central HEAD/dirty files, Unity version, model FBX/hash/import settings, animator controller and clip/contact contract alongside each native run. Previous `Binding.csproj` / 16 CPU checks at the parent output directory concern orientation only.

## Run and capture

1. Use Unity 6000.3.24f1 with `-noaudio`, unpaused Play Mode, main menu, no room/runtime. Alternatively the Director can mute AudioListener beforehand; the helper never changes or restores global volume. Keep the Game view rendering and keep the application focused. Do not create a second probe/session concurrently.
2. Run package `Load.cs` through eval_file, then `Start-floor-Continuous.cs`. Do the same for wall and ceiling in separate runs from the menu. Continuous mode is the temporal evidence pass: no manual freeze; samples are taken once per rendered frame of the owned presentation camera. The run ends by cancelling only its own practice and returns to the menu. `Status.cs` reports progress; `Stop.cs` performs cleanup. A round interruption, obstructed route or missing render is an inconclusive result, not an excuse to teleport or suppress bots.
3. For screenshots, separately run `Start-floor-Manual.cs` (and wall/ceiling variants). Poll `Status.cs` until `HOLDING`, capture the actual Game view and, if needed, a separate Scene-view closeup at the suggested world camera pose. Name the PNG with its run/checkpoint. The helper does not move any camera or generate PNGs. `Next.cs` resumes to the next checkpoint; after the last checkpoint it cancels the owned practice. A scene-camera image must be labelled separately from the game-camera sample. The nearest frame sampled at a checkpoint may follow several host ticks: see `ticksAfterAction`, never label it the first simulation tick without checking.
4. Check the final trace status, console and menu, no active probe, runtime or frozen character. Before switching package/recompiling, stop the active package. On Play exit/assembly reload, callbacks unregister, the file stream closes and the helper attempts normal practice cleanup. Missing render times out in 10 seconds; active runtime is bounded to 60 seconds/4000 sampled frames; manual holds expire after 10 minutes. No editor pause, global timescale change or background process is used.

## Route and measurements

The route uses normal W-direction inputs and F actions on a newly created local mosquito practice, keeping bots active. Current authored endpoints are floor `(3.6,.23,1.3)`, wall `(4.75,1.9,2)`, ceiling `(3.6,2.57,1.3)`; normals are +Y, -X and -Y. A query at the endpoint must confirm the desired plane. Routes may be obstructed after a map revision: report that and revise the diagnostic route, never the game rules. Walking points inward (-X for floor/ceiling, -Z for wall).

Phases: approach; reachable-plane query and F; attachment/settling; tangent aim; opposite tangent aim (180 degrees); aim away; two seconds of normal walking input; F detach; 0.8 seconds of flight away. Attachment begins looking toward the plane and detachment looks away. This is a bounded diagnostic route, not every possible orientation/entry/exit combination. Repeat/manual native tests cover remaining combinations and locomotion clips as needed.

`frames.jsonl` contains real rendered samples with Unity/editor/active times, phase, host tick, life state, physical velocity, MotionPhase, physical/visual roots, visual +Y dot plane normal, animator state/time, blend/next state and clip weights. No contact plane is invented before a surface is resolved. After detachment distances refer to the last support plane. Each checkpoint JSON captures the same evaluated measurement and records a separate screenshot/review requirement.

Contact uses `SkinnedMeshRenderer.BakeMesh` in world space, signed minimum clearance of the full mesh and each named distal foot group (`Leg103/203/303.L/R`, vertex weight >0.8). Missing/unreadable weights, changed names and incomplete foot coverage are explicit errors/coverage gaps. Distal geometry with blended weights below the cutoff is excluded. Per-foot centroids and nearest evaluated vertices allow comparison across frames. Tangential centroid movement while both sampled clearances are within 1.5 mm is an **apparent sliding proxy**, not proof that an individual contact vertex is planted. Root/GroundContact alone do not establish foot support. Plane clearances do not prove that the mesh avoids nearby finite edges or other colliders. Threshold counts are diagnostic and never visual approval.

Manual checkpoint freezes are diagnostic interruptions: host ticking and the owned binding/Animator stop, while Unity time and other visuals continue. After resuming, temporary animation timers may expire. Use continuous runs to judge transition timing, not the joined manual checkpoints. Two seconds of walking do not guarantee a complete cycle: inspect actual clip/time spans, state resets, blends and sample gaps. Record observed cycle coverage; do not count duplicated planes/poses as full clips. Record real speed, MotionPhase and Animator cycles against the modeler's eventual stride/duty/scale contract; the suspected 0.3 m runtime stride mismatch is not established by this helper or compilation.

## Acceptance remains external

`COMPLETE_UNREVIEWED` only means the bounded route reached its checkpoints. Review frames, gaps, foot coverage, penetration/hovering, 180-degree turns, supporting-foot count, apparent sliding and entry/exit deformation with the native images/motion. Sampling/JSON writing affects frame time, so this is not an FPS benchmark. Acceptance requires the integrated model and complete relevant clip/transition review by Director/reviewer; no runtime execution has occurred merely because this package compiled.
