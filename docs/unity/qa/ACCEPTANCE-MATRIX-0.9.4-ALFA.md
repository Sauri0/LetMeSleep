# Matriz de aceptación funcional — Unity 0.9.4 alfa

## Uso y regla de dictamen

Esta matriz cubre exclusivamente `0.9.4-alfa`: una casa fija con patio, lobby separado, modo Sangre, entrenamiento, personalización base, una herramienta de prueba, EOS y distribución Windows. Supervivencia, Tareas, catálogo amplio, inventario de tres espacios, estamina y voz no se habilitan en esta entrega.

Cada gate tiene tres estados posibles:

- **PREPARADO**: existe este contrato o su test, pero aún no hay corrida aceptable.
- **PASS**: la evidencia indicada se ejecutó sobre el mismo commit y build candidato, con código 0, logs sin excepciones y los negativos rechazados.
- **BLOCK**: falta evidencia, el negativo no detecta la falla, o hay un defecto reproducible.

Un test EditMode aislado no acredita animación, render, física PlayMode, red real, WAN ni instalación. Una captura no acredita autoridad o colisión. Los recibos deben registrar commit, Unity `6000.3.24f1`, plataforma, escena, argumentos/configuración, duración, resultado y SHA-256 del ejecutable cuando aplique.

## Reglas de evidencia

1. El negativo se ejecuta en fixture/copia; jamás se modifica el candidato para una corrida positiva.
2. Los tests deben fallar si se inyecta su defecto objetivo. Un PASS que no distingue el mutante no acredita el gate.
3. EditMode, PlayMode, build nativo, EOS local, WAN y launcher se reportan por separado.
4. Toda evidencia queda ligada al commit y, cuando existe, al SHA-256 exacto del ejecutable/ZIP.
5. U094-13, U094-16 y U094-17 no pueden completarse por inferencia desde código o resultados Godot.
